Tu vas créer le squelette CI/CD complet du projet SealKeeper, conformément aux spécifications déjà commitées dans `docs/prd/`.

CONTEXTE
========

SealKeeper est un distributeur de mots de passe ANSSI-compliant, écrit en Go (backend) + JavaScript (bundle générateur navigateur), distribué sous AGPL v3. Le PRD complet est figé en v1.0 — il est la référence canonique pour toute décision.

**Objectif de cette tâche** : livrer une **stack Docker prête à déployer immédiatement**. Le résultat doit permettre à un évaluateur de cloner le repo, lire 3 lignes du QUICKSTART, lancer `docker compose up -d` ou un `docker run` one-liner, et avoir une instance fonctionnelle en moins de 5 minutes. Le CI/CD doit produire à la fois :
- Les **binaires** signés et reproductibles
- L'**image OCI distroless** multi-arch poussée sur ghcr.io
- Le **bundle de déploiement complet** (docker-compose + .env.example + Caddyfile + manifests K8s + Helm chart) testé end-to-end avant publication

L'image Docker seule ne suffit pas. Le smoke test de release doit valider que **le déploiement Compose complet fonctionne** avant que la release ne soit publiée.

   **Smoke test du bundle Compose** (stage à insérer APRÈS l'assemblage du bundle, AVANT la création de la GitHub Release) :
   - Extraire le bundle dans un dossier temporaire CI
   - Générer un master secret factice via `openssl rand -base64 32`
   - Renseigner le `.env` minimal nécessaire (master secret, SK_BASE_URL=http://localhost:8443, SK_MODE=eval pour le test)
   - Exécuter `docker compose up -d`
   - Attendre que le healthcheck soit vert (boucle sur `/healthz` avec timeout 60s)
   - Faire un `curl` sur la page publique `/` (vérifier 200 OK)
   - Faire un `curl` sur `/api/v1/policy` (vérifier 200 OK avec JSON)
   - Vérifier qu'un email de demande déclenche bien une capture (route `/__captured_mail` en mode eval)
   - Tear down propre (`docker compose down -v`)
   - **Si une seule de ces vérifications échoue, la release entière est annulée**

   **Mode eval one-liner** documenté dans les notes de release :
docker run --rm -p 8443:8443 -e SK_MODE=eval ghcr.io/sealkeeper/sealkeeper:<version>
   Doit fonctionner sans aucune config additionnelle (master secret auto-généré, SQLite, bootstrap admin password en logs — conforme FR-H.11 à FR-H.19).
